01

문제 정의

웨어러블 기기는 심박수·산소포화도·체온을 초 단위로 수집한다. 이 데이터를 어디에 저장하고, 어떤 기준으로 "위험"을 판별할 것인가가 헬스케어 데이터 파이프라인의 출발점이다. 이 프로젝트는 두 계층을 동시에 다뤘다.

① 저장 계층 — 동일 데이터를 관계형(MySQL)과 문서형(MongoDB)에 각각 적재해 두 패러다임의 조회 방식을 비교했다. ② 분석 계층 — 저장된 데이터에서 임상적으로 의미 있는 이상 신호를 규칙 기반으로 탐지하고, 그 결과의 타당성까지 역검증했다.

03

핵심 구현 — 하나의 분석, 두 개의 쿼리

활동별 평균 생체지표를 SQLAlchemy Core와 MongoDB Aggregation 두 방식으로 구현하고 결과 일치를 검증했다. GROUP BY = $group, WHERE = $match의 대응 관계를 직접 매핑했다.

SQLAlchemy CoreRelational
select(
    biometric.c.activity,
    func.avg(biometric.c.heart_rate),
    func.avg(biometric.c.step_count),
).group_by(
    biometric.c.activity
)
MongoDB AggregationDocument
col.aggregate([
  {"$group": {
    "_id": "$activity",
    "avg_hr": {"$avg": "$heart_rate"},
    "avg_step": {"$avg": "$step_count"},
  }},
  {"$sort": {"_id": 1}},
])

06

데이터 품질 검증 ★ 차별점

쿼리 결과를 나열하는 데 그치지 않고, 결과의 타당성을 역검증하는 과정에서 데이터 신뢰성의 한계를 발견했다.

FINDING 01

불가능한 관측값

체온 이상치 최댓값이 48.7°C — 인체에서 나올 수 없는 값. 실서비스라면 상한 클리핑·결측 처리가 필요한 구간.

max 48.7°C
FINDING 02

활동–심박수 무상관

Running(118)과 Resting(121)의 평균 심박이 사실상 동일. 운동 시 상승해야 할 심박이 반응하지 않아 합성 데이터 가능성을 시사.

Δ ≈ 3 bpm
FINDING 03

과도한 이상치 비율

저산소 41%·발열 35% 등 비율이 비현실적으로 높음. 임계값 튜닝 없이 규칙을 적용하면 대량의 거짓 경보가 발생함을 진단.

SpO₂ 41%
Insight

분석 파이프라인이 정확히 동작하더라도, 입력 데이터의 신뢰성이 검증되지 않으면 결과 해석은 무의미하다. "쿼리를 잘 짜는 것"만큼 "결과가 현실적으로 말이 되는지 되묻는 것"이 데이터 품질 관리의 핵심임을 확인한 사례.

07

배운 점 & 트러블슈팅

  • A

    이종 DB 조회 패러다임 매핑

    SQL의 SELECT-WHERE-GROUP BY-ORDER BY가 MongoDB의 $project-$match-$group-$sort에 어떻게 대응되는지 직접 구현하며 체득.

  • B

    MongoDB 필드 순서 제어

    집계 결과의 필드 순서가 유지되지 않는 문제를 OrderedDict·bson.SON으로 명시적으로 해결.

  • C

    규칙 기반 이상 탐지의 한계

    고정 임계값은 구현이 단순하지만 데이터 분포에 따라 오탐이 폭증할 수 있음을 수치로 확인.
